## verl-omni module map for reviewers

verl-omni is built **on top of** upstream verl, which is an installed git dependency pinned at `.github/verl_pin.txt` (= the `train` extra in `pyproject.toml`; the two must move together). It is not vendored: everything generic — `verl.single_controller.*`, `DataProto`, `verl.trainer.ppo.*` (incl. the v1 trainers and `register_trainer`), `verl.workers.*` (EngineRegistry, rollout replica/LLM-server stack, config dataclasses), `verl.experimental.{agent_loop,reward_loop}`, `verl.base_config.BaseConfig`, `verl.utils.device` — comes from upstream. verl-omni adds diffusion-RL (FlowGRPO family) and omni-model (Qwen3-Omni) specializations. Rollout backend is vLLM-Omni, pinned at `.github/vllm_omni_pin.txt` (NPU: `.github/vllm_ascend_pin.txt`). There is **no** `verl_omni/single_controller/` — that layer lives entirely upstream.

`import verl_omni` has heavy side effects (`verl_omni/__init__.py`): it imports `models`, `pipelines`, `reward_loop`, `trainer`, `workers.engine`, `workers.rollout` purely to populate registries and apply monkey-patches, and sets a CPU fallback for vllm-omni's platform device_type. Any new module-scope heavy import in those trees breaks CPU CI (`tests/special_sanity/test_import.py`) — lazy imports inside methods are the rule.

### Trainer entrypoints — `verl_omni/trainer/`
- **Purpose**: `main_diffusion.py` (v0 Ray trainer: `PolicyGradientRayTrainer` / `DirectPreferenceRayTrainer` in `verl_omni/trainer/diffusion/ray_diffusion_trainer.py`, selected by `algorithm.trainer_type`), `main_diffusion_v1.py` (v1: TransferQueue force-enabled, trainer picked by `config.trainer.v1.trainer_mode` from verl-omni's own `register_diffusion_trainer` registry in `verl_omni/trainer/diffusion/v1/trainer_base.py` — `"sync"` in `trainer_sync.py`, `"separate_async"` in `trainer_separate_async.py`), `main_omni.py` (delegates to upstream `verl.trainer.main_ppo.run_ppo` with `TaskRunnerV1`; forces `trainer.use_v1=True`; omni trainers register into **upstream's** `@register_trainer` registry: `"omni_sync"` in `verl_omni/trainer/omni/ray_omni_trainer.py`, `"omni_fully_async"` in `ray_omni_trainer_fully_async.py`).
- **Blast radius**: trainer changes affect every algorithm and both device families; `compute_advantage` in `ray_diffusion_trainer.py` is imported by the v1 trainers too, so v0 edits leak into v1.
- **Pitfalls**: two similarly named registries (`register_diffusion_trainer` = local; `@register_trainer` = upstream v1). The fully-async trainer validates staleness against `trainer.v1.sampler.max_off_policy_threshold` with strategy-dependent strictness and rejects `weight_sync_exclude_frozen` + `load_format=dummy` — those invariants are load-bearing.
- **Review focus**: does the change belong in the shared base (`trainer_base.py` / `BaseRayDiffusionTrainer`) or one subclass? Does it silently change v0 behavior via shared helpers?

### Algorithm registries — `verl_omni/trainer/diffusion/diffusion_algos.py`
- **Purpose**: `DIFFUSION_LOSS_REGISTRY` (`@register_diffusion_loss`: flow_grpo, dance_grpo, flow_dppo, grpo_guard, dpo, diffusion_nft, kl, distill_kl, distill_fm_mse) and `DIFFUSION_ADV_ESTIMATOR_REGISTRY` (`@register_diffusion_adv_est`). All losses subclass `DiffusionLossFn`.
- **Blast radius**: every diffusion algorithm's math. `rollout_correction.py` (IS correction / logprob bypass) sits next to it and is consumed by v0 and v1.
- **Pitfalls**: a new loss name must ALSO be added to `valid_modes` in `DiffusionLossConfig.__post_init__` (`verl_omni/workers/config/diffusion/actor.py`) or config validation rejects it. `algorithm.adv_estimator` and `actor.diffusion_loss.loss_mode` both default to `${oc.select:actor_rollout_ref.model.algorithm,flow_grpo}` — one CLI knob cascades into three places.
- **Review focus**: numerical changes need `tests/trainer/diffusion/test_diffusion_core_algos_on_cpu.py` updates and may shift the L3 nightly baseline (`tests/nightly/qwen_image_flowgrpo/`, compared at atol 1e-4 / rtol 1e-3 / cos-sim 0.999 and 10% metric threshold).

### Config system — `verl_omni/trainer/config/` + `verl_omni/workers/config/`
- **Purpose**: 16 dataclasses (2 in `trainer/config/algorithm.py`, 14 under `workers/config/{diffusion,omni}/`), all extending upstream `verl.base_config.BaseConfig` or upstream worker configs (`OmniActorConfig` extends `verl.workers.config.FSDPActorConfig`; `VeOmniDiffusionEngineConfig` extends upstream `EngineConfig`). Hydra roots: `diffusion_trainer.yaml` (standalone; `diffusion/model_engine` group swaps the whole FSDP↔VeOmni actor/ref pair) and `omni_trainer.yaml` (composes **upstream** `ppo_trainer` via `hydra.searchpath: pkg://verl.trainer.config`).
- **Blast radius**: highest in the repo relative to visibility — renames break user YAML, 60+ scripts under `examples/`, and (for omni) the overlay on upstream keys; field renames/removals require a `[BREAKING]` PR title.
- **Pitfalls**: `_generated_*.yaml` are never hand-edited (regenerate via `scripts/generate_trainer_config.sh`; the script silently skips the omni file when verl isn't installed, so local green ≠ CI green). New `DiffusionPipelineConfig` fields must be mirrored in BOTH `trainer/config/diffusion/rollout/diffusion_rollout.yaml` (`pipeline:` and `val_kwargs.pipeline:`) and `trainer/config/diffusion/model/diffusion_model.yaml`. Config style: `_mutable_fields` allowlist, `MISSING` + `__post_init__` set-membership validation, `#`-comment-above-field doc format gated by `tests/special_sanity/test_config_docs.py` (9-file allowlist, NOT omni_trainer.yaml). `__post_init__` does real I/O in places (tokenizer load; `attn_backend=_flash_3_varlen_hub` hard-imports `kernels`).
- **Review focus**: three-step wiring (module `__all__` → yaml `_target_` → `omega_conf_to_dataclass`, never `hydra.utils.instantiate` outside the agent loop); `${oc.select:}` cascades; defaults sanity (`rollout.n: 1`, `lora_rank: 0` off-by-default, diffusion `lora_alpha: 64` vs omni `lora_alpha: 16`, `load_format: dummy`, val `num_inference_steps: 50` vs train 10).

### Pipelines — `verl_omni/pipelines/`
- **Purpose**: one package per `(architecture, algorithm)` integration, each = `diffusers_training_adapter.py` (subclass of `DiffusionModelBase`/`DiffusionI2IModelBase` in `verl_omni/pipelines/model_base.py`, registered `@DiffusionModelBase.register(arch, algorithm=...)`) + `vllm_omni_rollout_adapter.py` (`@VllmOmniPipelineBase.register(...)`, subclasses a concrete vllm-omni pipeline). Omni analog: `OmniModelBase` keyed `(architecture, stage)` + `OmniRolloutPipelineBase` keyed on vLLM-Omni `model_type` (`verl_omni/pipelines/qwen3_omni/`). Shared: `schedulers/flow_match_sde.py` (must return `(prev_sample, log_prob, prev_sample_mean, std_dev_t)`), `request_batch.py` (stepwise continuous batching), `non_diffusers_model_base.py` (models diffusers can't load, e.g. BAGEL), `utils.py` (`ImageGenerationRequest`).
- **Blast radius**: `model_base.py` signature changes fan out to all 10 packages plus out-of-tree `external_lib` users; `forward_and_sample_previous_step`'s 4-tuple is consumed by `PPODiffusersFSDPEngine.prepare_model_outputs`.
- **Pitfalls**: registration is an import side effect — a package absent from `verl_omni/pipelines/__init__.py` silently doesn't exist. Architecture string must equal `model_index.json::_class_name` verbatim. Training adapters are **stateless** (classmethods only, no `__init__`); rollout adapters are instantiated. Rollout `custom_output` key names are contracts read by the agent loop (`prompt_embeds{,_mask}`, `negative_prompt_embeds{,_mask}`, `all_latents`/`all_log_probs`/`all_timesteps`, `latents_clean`); I2I condition tensors must travel as `condition_image_latents` — `image_latents`/`latents_clean`/`all_latents`/`audio_latents` are reserved by the MFU FLOPs counter. Never merge two registered adapters into one class with an `if algorithm ==` switch. `get_class` applies the Qwen-Image Ulysses monkey-patch as a side effect.
- **Review focus**: lazy diffusers/vllm_omni imports (CPU importability), a `tests/pipelines/test_*_on_cpu.py`, correct registry key, tunables in `workers/config/diffusion/` not module constants.

### Workers: engine worker + engines — `verl_omni/workers/engine_workers.py`, `verl_omni/workers/engine/`
- **Purpose**: `ActorRolloutRefWorker` (and Tinker-style `TrainingWorker`) in `engine_workers.py` is the single colocated actor/rollout/ref worker used by **all** trainer families (v0/v1 diffusion, omni sync, omni fully-async); it bridges upstream single_controller dispatch to engines and owns weight sync incl. the LoRA adapter-only path upstream lacks. Engines register into upstream `EngineRegistry`: `PPODiffusersFSDPEngine` (`model_type="diffusion_model"`), `DPODiffusersFSDPEngine` (`diffusion_dpo_model`), `NFTDiffusersFSDPEngine` (`diffusion_nft_model`) in `engine/fsdp/diffusers_impl.py`; `OmniFSDPEngine` (`omni_model`) in `engine/fsdp/omni_impl.py`; `VeOmniDiffusionEngine` (backend `veomni`, **cuda only**) in `engine/veomni/diffusion_impl.py`, optional via try/except in `engine/__init__.py`. `engine/lora_adapter_mixin.py` handles multi-adapter (`default`/`old`) policy state.
- **Blast radius**: the largest in the repo — a wrong change here breaks every trainer at once, usually only visible on GPU (CI: gpu_smoke `ci-core` + both e2e groups).
- **Pitfalls**: **DataProto is banned under `workers/engine/`** (pre-commit `check-dataproto-usage`) — TensorDict only. Hardcoded `"cuda"`/`.cuda`/`"nccl"` banned repo-wide (`check-device-api-usage`; `diffusers_impl.py` is whitelist-exempted, don't extend the exemption casually). NPU branch: `TrainingWorker.__init__` sets `PYTORCH_NPU_ALLOC_CONF=expandable_segments:True`.
- **Review focus**: dispatch decorator correctness (`verl.single_controller.base.decorator`), weight-sync paths (bucketed sender, per-update ZMQ handles, LoRA peft_config flow), engine `model_type` key choices.

### Rollout — `verl_omni/workers/rollout/`
- **Purpose**: registers `vllm_omni` into upstream registries (`base.py` → `_ROLLOUT_REGISTRY[("vllm_omni","async")]` pointing at an **upstream** ServerAdapter; `replica.py` → `RolloutReplicaRegistry.register("vllm_omni", ...)` lazily loading `vLLMOmniReplica`). `vllm_rollout/vllm_omni_async_server.py` (842 lines) is the async server around vLLM-Omni (`npu_utils.py` for Ascend). `retry_llm_server.py` `WholeSampleRetryLLMServerClient` retries whole samples on abort (max 50) and tracks min/max weight versions for staleness metrics; `diffusion_llm_server.py` is a back-compat alias. `checkpoint_engine.py` (`OmniCheckpointEngineManager`) pushes LoRA peft_config to standalone replicas pre-sync.
- **Blast radius**: all online sampling (actor rollout AND reward-model serving — reward servers reuse the same replica stack).
- **Pitfalls**: tightly coupled to the vllm-omni git pin; a pin bump in `.github/vllm_omni_pin.txt` can break this file and every CI job installs from it. `DiffusionOutput.stop_reason` strings ("aborted"/"abort") drive retry logic. Rollout runs with `skip_tokenizer_init=True` — tokenization happens once in the agent loop; never decode-and-re-encode.
- **Review focus**: pin bumps must ride with server changes; recovery semantics vs the fully-async trainer's `rollout_recovery` modes.

### Agent loop — `verl_omni/agent_loop/`
- **Purpose**: diffusion generation loops on upstream `verl.experimental.agent_loop`. `single_turn_agent_loop.py` registers `@register("diffusion_single_turn_agent")` (upstream registry): vision info → chat template → per-extra-encoder tokenization (`extra_tokenizer_map`, one entry per distinct tokenizer vocab, e.g. SD3.5 clip/t5) → one `generate` call. `diffusion_agent_loop.py` = v0 worker + `DiffusionAgentLoopOutput`; `diffusion_agent_loop_tq.py` = TransferQueue v1 worker + `create_diffusion_agent_loop_manager` (wires upstream `AgentLoopManagerTQ`); `utils.py` = per-rollout seeding.
- **Blast radius**: data-format bridge between rollout output and training micro-batches; key renames here corrupt training silently.
- **Pitfalls**: constructor signature is pinned to upstream `AgentLoopManager.create()` positional args (`teacher_client` accepted but unused). Truncate in the agent loop, pad in the rollout adapter.
- **Review focus**: this is the multi-turn/multi-agent seam (see extension seams) — keep `num_turns` and `extra_fields` plumbing intact.

### Reward — `verl_omni/reward_loop/` + `verl_omni/utils/reward_score/`
- **Purpose**: `reward_loop.py` `OmniRewardLoopManager` (upstream `RewardLoopManager` + profiler fan-out); managers `reward_manager/visual.py` and `multi.py` resolve scorers and emit `rm_scores` + metrics. Scorers (one file each): jpeg_compressibility, choice_reward, mmk12_reward, genrm_ocr, hpsv3_reward, pickscore_reward, unified_reward, http_scorer_client, latent_http_scorer_client.
- **Blast radius**: reward semantics = training signal; manager changes affect every online run.
- **Pitfalls**: scorers are selected **by config** (`reward.custom_reward_function.{path,name}` or `reward.reward_functions.<key>.{path,name,weight,required,+kwargs}`), never by editing the single-branch fallback in `reward_score/__init__.py`. Managers call scorers **by keyword** — parameter names are the contract (`data_source, solution_image, ground_truth, extra_info, **kwargs` → dict with `"score"`). `MultiVisualRewardManager` catches per-sub-reward failures (→0.0 unless `required: true`); `VisualRewardManager` does not — a raise propagates. One shared `reward_router_address` across sub-rewards. Device inconsistency to flag: `hpsv3_reward.py` defaults `device="npu"`, `pickscore_reward.py` defaults `device="cuda"`; both are check_device_api_usage whitelist entries. `http_scorer_client` returns `{"score": 0.0}` on HTTP failure (silent); `latent_http_scorer_client` raises after retries.
- **Review focus**: signature compliance, model caching in module globals (not per call), CPU test in `tests/utils/reward_score/`.

### utils + models patches — `verl_omni/utils/`, `verl_omni/models/`
- **Purpose**: datasets (`utils/dataset/rl_dataset.py` adds `negative_prompt_key`; `omni_rl_datasets.py` Qwen-omni mm ordering; `offline_dpo_dataset.py` / `offline_mllm_dpo_dataset.py` paired-preference contracts with adjacent [win, lose] rows; `qwen3_omni_transform.py` re-implements VeOmni's sample processing to avoid the dep; `visual_reflection/` pure-stdlib multi-turn data toolkit), FS/FSDP helpers (`utils/fs.py`, `utils/fsdp_utils.py` LoRA collection with FSDP2/diffusers-layered branch), `utils/diffusion_attention.py` (FA3 probing + actor/rollout backend consistency; skips validation for veomni strategy; the one legit hardcoded-CUDA site), `utils/mfu/` (`@register_diffusion_architecture` registry; unregistered arch → MFU 0 with a warning, not an error), `utils/vllm_omni/utils.py` (`VLLMOmniHijack` enabling in-memory LoRA tensor loading). `models/` = monkey-patches: `diffusers/flash_attention_3.py` (FA3 varlen non-contiguous-mask fix, **applied unconditionally at `verl_omni.models` import**), `diffusers/qwen_image.py` (Ulysses mask fix, applied only via `DiffusionModelBase.get_class`), `transformers/qwen3_omni_thinker.py` (five patches applied at module import: AutoModel registration into verl's `_architecture_to_auto_class`, hf_processor/hf_tokenizer wrappers, MoE expert unfusing for PEFT, vllm MoE weight-loader whitelist append).
- **Blast radius**: patches mutate upstream (verl / diffusers / peft / vllm) dicts and functions — version bumps of any of those can invalidate them; all are version-guarded and idempotent today, keep them that way.
- **Pitfalls**: patches carry removal TODOs tied to upstream fixes — a diffusers/transformers/verl bump PR must re-evaluate each. `models/transformers/__init__.py` is intentionally empty; the thinker module is imported explicitly.
- **Review focus**: any patch edit needs the "why" comment preserved, a version guard, and an idempotency sentinel.

### Tests & CI — `tests/`, `.github/workflows/`
- **Purpose/structure**: CPU tier = `test_*_on_cpu.py` (selection is by filename via a generated `pytest.ini`, **not gated** — a misnamed test never runs); placement gate = `tests/special_sanity/validate_structure.py` (tests must live in `tests/<first-level-verl_omni-dir>/` or `special_{e2e,sanity,standalone,distributed}`). GPU tests sit beside CPU tests with plain names; `tests/gpu_smoke/` holds only shell scripts + `select_gpu_smoke_groups.py` (groups `ci-core` 2 GPU, `ci-e2e-omni` 2 GPU, `ci-e2e-diffusion` 4 GPU; path-pattern selection, fail-open to all groups on unknown paths). Workflows: `cpu_unit_tests.yml`, `sanity.yml` (pytest special_sanity collects only `test_config_docs.py` + `test_import.py`; the check_* scripts run via pre-commit), `pre-commit.yml` (the real home of license/device/dataproto/structure/naming/autogen-cfg gates), `doc.yml`, `type-coverage-check.yml` (0.3 annotation ratio on diff + `check_api_docs.py verl_omni`: every `__all__` export needs a docstring), `gpu_smoke.yml` (label-gated: `ready-for-ci` or a group label; labels are stripped on every push by `drop-ci-labels.yml`), `gpu_smoke_verl_latest.yml` (verl@main drift check, currently workflow_dispatch-only and non-blocking), `l3_nightly.yml` (deterministic 20-step Qwen-Image FlowGRPO vs stored `l3-nightly-baseline` artifact; exact label `L3-nightly-ci`), `secrets_scan.yml`, `check-pr-title.yml`.
- **Review focus**: PR title `[{modules}] {type}: {description}` — modules from `tests/special_sanity/check_pr_title.py`: fsdp, vllm_omni, rollout, trainer, ci, training_utils, recipe, ray, worker, single_controller, misc, perf, model, algo, env, tool, ckpt, doc, data, cfg, reward, diffusion, omni, tests, docker; types: feat, fix, refactor, chore, test; `[BREAKING]` prefix for API/config breaks. New e2e scripts follow `tests/special_e2e/run_<algo>_<model>.sh` against tiny-random checkpoints and get registered in the right `tests/gpu_smoke/run_gpu_smoke_*.sh` + path filters in `gpu_smoke.yml`.

## Upstream alignment rules

"Upstream-aligned" concretely means, and reviewers should flag divergence from:
1. **Extend, don't fork**: subclass upstream classes (`OmniPPOTrainerSync(PPOTrainerSync)`, `OmniCheckpointEngineManager(CheckpointEngineManager)`, `OmniRewardLoopManager(RewardLoopManager)`) or register into upstream registries (`EngineRegistry`, `RolloutReplicaRegistry`, `_ROLLOUT_REGISTRY`, agent-loop `@register`, v1 `@register_trainer`). Copying upstream code where a subclass/registry entry would do is gratuitous divergence.
2. **Config style**: hydra defaults-list composition; `_target_` + `omega_conf_to_dataclass` (from `verl.utils.config`); dataclasses inherit `verl.base_config.BaseConfig`, use `_mutable_fields` and `MISSING`+`__post_init__` (no `frozen=True`, no `Literal`). `omni_trainer.yaml` composes upstream `ppo_trainer` via `pkg://verl.trainer.config` — an upstream config-key rename silently breaks the overlay, so verl pin bumps need config re-verification.
3. **Device API**: `verl.utils.device` (`get_device_name`, `is_cuda_available`, `is_npu_available`, `auto_set_device`); no literal `"cuda"`/`.cuda`/`"nccl"` (gated).
4. **File placement mirrors upstream**: trainers under `trainer/`, engines+rollout+configs under `workers/`, sanity checks under `tests/special_sanity/`; AGENTS.md/CI conventions adapted from upstream verl (which adapted vLLM's).
5. **Pin discipline**: `.github/verl_pin.txt` must equal the pyproject `train` extra commit; upstream-behavior-dependent changes must bump both (and can be sanity-checked against `gpu_smoke_verl_latest`). vllm-omni server code (`vllm_omni_async_server.py`) moves with `.github/vllm_omni_pin.txt`.
6. Shared PPO/FSDP/optim config fields are documented upstream only (`docs/examples/config.md`) — don't re-document or rename them here.

## Extension seams

- **New diffusion pipeline**: new package `verl_omni/pipelines/<model>_<algo>/` with training + rollout adapters, registered on `(model_index.json _class_name, algorithm)`; MUST be star-imported in `verl_omni/pipelines/__init__.py`; guides in `docs/contributing/integrating_a_diffusion_model.md` (+ `integrating_an_i2i_diffusion_model.md`, `integrating_a_non_diffusers_model.md` — CLI `+actor_rollout_ref.model.architecture=...` when no model_index.json, `integrating_a_stepwise_continuous_batching_model.md` — add lifecycle methods to the existing adapter, never a new `_stepwise` registration). Out-of-tree: `DiffusionModelConfig.external_lib`.
- **New omni model**: `@OmniModelBase.register(architecture, stage=...)` + optional `@OmniRolloutPipelineBase.register(model_type)`; transformers patches in `verl_omni/models/transformers/`; guide `docs/contributing/integrating_an_omni_model.md`; adapters stay algorithm-agnostic (algorithm comes from upstream `actor.policy_loss.loss_mode` / `algorithm.adv_estimator`).
- **New reward**: one file in `verl_omni/utils/reward_score/` following the keyword contract; wired purely by config; skill `.agents/skills/add-reward-score/SKILL.md`, rules `.agents/rules/reward.md`.
- **New algorithm**: policy-gradient = SDE branch in `verl_omni/pipelines/schedulers/flow_match_sde.py` + `@register_diffusion_adv_est` + `@register_diffusion_loss` + `valid_modes` entry + adapter pair; direct-preference = loss + possibly a new engine (`@EngineRegistry.register(model_type="<algo>_model", ...)` in `engine/fsdp/diffusers_impl.py`) selected via `actor_rollout_ref.model.model_type`; guides `docs/contributing/integrating_a_new_{policy_gradient,direct_preference}_algorithm_for_diffusion_model.md`.
- **Multi-agent / multi-step (future)**: seams are upstream's agent-loop registry + the `rollout.agent.agent_loop_manager_class` FQN override in `main_diffusion_v1.py`, `num_turns`/`extra_fields` in `DiffusionAgentLoopOutput`, and the `utils/dataset/visual_reflection/` toolkit (multi-turn edit/reflect data; pure stdlib, fail-closed). Currently rigid: `DiffusionSingleTurnAgentLoop` hardwires one generate call; reward managers assume single image/latent tensors; one shared reward router address. RFC groundwork for fully-async omni lives in `notes/qwen3omni_fully_async/RFC.md` (the shipped `omni_fully_async` trainer is its first slice).
